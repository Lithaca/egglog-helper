# egglog-helper 首版设计

目标目录：`E:\Coding\egglog-helper`
面向语言：Go
日期：2026-10-21

## 目标

做一个能在日常 Go 项目中运行的本地命令行工具：发现复杂条件中可消除的重复、冗余和矛盾，输出更简洁且在支持范围内等价的建议。项目同时作为学习 egglog 的小型、可扩展实践。

首版成功标准：在一个 Go 模块中运行一条命令，得到带文件名、行列号、原表达式和建议表达式的结果；在真实 egglog 引擎参与的端到端测试中验证这些结果。

## 使用方式

```text
egglog-helper check ./...
egglog-helper check ./internal/auth
egglog-helper check -json ./...
```

报告示例（示意）：

```text
internal/auth/permission.go:24:5: condition can be simplified
  before: (enabled && admin) || (enabled && !admin)
  after:  enabled
```

其中 enabled、admin 必须是通过类型与语法检查的局部布尔值或参数。

首版提供建议，不直接修改被检查项目。普通文本用于终端，JSON 用于后续编辑器集成。退出码约定为 0（没有建议）、1（存在建议）、2（配置、加载或引擎错误）。

## 首版范围

- 扫描 `if` 和带条件的 `for`，遵循 Go 包模式与构建约束。
- 支持布尔常量、局部布尔变量、参数、括号、`!`、`&&`、`||`。
- 支持经过类型检查的简单比较：局部整数或字符串值的比较，以及可安全判断的 nil 比较。比较作为独立布尔命题参与组合优化，不推导数值区间。
- 发现重复条件、吸收律、互补条件、常量条件和可消除的双重否定。例如 `a || (a && b)` 变为 `a`。
- 对生成代码默认跳过；类型错误和引擎故障明确报告，不能伪装成“未发现问题”。

复杂的字段访问、函数或方法调用、下标、解引用、通道接收、类型断言，以及无法确认安全的表达式，首版整体跳过。暂不进行跨语句推导，不改写循环结构，不支持自动批量修复。

## Go 语义约束

Go 的逻辑运算具有短路求值语义；只判断真假等价，不足以保证代码改写合法。因此先用 Go AST 和类型信息筛选允许进入引擎的表达式，再让 egglog 对筛选后的纯布尔表达式做重写。

例如 `p != nil && p.Ready` 和 `check() || true` 不进入首版优化。`true`、`false`、`nil`、变量和比较的含义以类型检查结果为准，不能仅根据标识符文本猜测。

每个建议还由 Go 端独立枚举布尔命题的真值组合进行校验。首版每个表达式最多八个独立命题，超过上限跳过；真值检查是对引擎输出的交叉检查，不能替代前面的 Go 语义筛选。

## 实现结构

采用 Go 前端调用独立 egglog 进程的方案，规则保存在可阅读的 `.egg` 文件中。

1. Go 前端使用 `go/packages` 加载项目，读取 AST、标识符绑定和类型信息。
2. 筛选允许处理的条件，并转换成小型布尔表达式表示；命题使用内部编号，避免直接拼接用户源代码到规则中。
3. 调用固定版本的官方 egglog 引擎，按规则探索等价候选并提取成本更低的表达式。
4. Go 前端严格解析返回结果，做独立真值校验，再还原 Go 代码和位置。
5. 输出文本或 JSON 诊断。

候选成本首先衡量表达式大小；只报告严格变简单的结果，避免同等成本的表达式来回换顺序。规则运行设置轮数、输入规模和进程时间限制。对相同表达式复用结果，减少重复启动引擎。

相比自己实现 Go 版重写器，这个方案直接使用 egglog；相比在 Go 中嵌入 Rust FFI，进程接口更容易调试和维护。代价是安装时需要同时提供 Go 命令行程序与 egglog 引擎。

目标环境已有 Go 和 Cargo。官方 egglog 0.4.0 可由当前 Cargo 1.83 编译，版本固定在 Windows PowerShell 构建脚本中，工具和引擎安装在项目目录内。

## 交付内容

- Go 命令行源代码、独立 egglog 规则与固定的依赖配置。
- 安装、构建和运行说明，优先覆盖当前 Windows 环境。
- 可直接运行的 Go 示例，包括能简化和应跳过的案例。
- 单元测试、包含真实 egglog 的集成测试，以及 JSON 输出示例。

## 验收

1. 重复、吸收、互补、双重否定和常量相关案例得到预期建议。
2. 函数调用、nil 保护后的字段访问、下标等案例不产生不安全建议。
3. 标识符遮蔽、命名布尔类型、括号优先级和生成代码得到正确处理。
4. 每条返回建议通过独立真值检查；解析错误或等价检查失败不能作为有效建议输出。
5. 示例模块的 `check ./...` 和 `-json` 端到端运行成功，报告的位置正确，示例源码没有被改动。
6. 引擎缺失、超时以及 Go 包加载失败时，给出可操作的错误说明。

## 后续扩展

首版完成并在用户日常项目中试用后，再根据实际命中率决定增加安全表达式类型、提供补丁预览，或接入编辑器。不在首版同时建设编辑器插件和通用代码优化平台。
